# EPS 引导修复工具 — 方案

## 定位
UI 只干三件事：**读环境、收集用户选择、调系统原生命令**。
BCD / EFI 底层一律不自己实现，全走 `bcdboot` / `bootrec` / `diskpart` / `bcdedit`。

## 一、两个独立判断（别混）

| 判断项 | 取值 | 获取方式 |
|---|---|---|
| 当前启动固件 | UEFI / Legacy | `GetFirmwareType()`（kernel32）。老 PE 降级读注册表 `HKLM\SYSTEM\CurrentControlSet\Control\PEFirmwareType`，2=UEFI，1=BIOS |
| 磁盘分区表 | GPT / MBR | WMI `Win32_DiskDrive.PartitionStyle`，1=MBR，2=GPT |

**关键**：磁盘是 GPT ≠ 当前是 UEFI 启动。修复分支**只认固件模式**，分区表仅用于交叉校验。

ESP 特征：FAT32 + PartitionTypeGUID `c12a7328-f81f-11d2-ba4b-00a0c93ec93b`，通常 100–500 MB。

## 二、主流程
1. 启动即校验管理员权限，非管理员弹窗退出
2. 自动读固件模式，Label 只读显示
3. WMI 枚举全部分区 → 下拉框，**用户手动选 Windows 系统分区**（PE 里系统盘不一定是 C）
4. 校验该分区存在 `\Windows\System32`；不通过只警告，允许强行走
5. 读该分区所属磁盘的 PartitionStyle，与固件模式配对：

| 固件 | 分区表 | 处理 |
|---|---|---|
| UEFI | GPT | ✅ UEFI 分支 |
| Legacy | MBR | ✅ Legacy 分支 |
| UEFI | MBR | ⚠️ 不合法，标红，**禁用一键修复** |
| Legacy | GPT | ⚠️ 标红，**禁用一键修复** |

6. 执行，stdout/stderr 实时追加到日志框
7. 结束弹窗报结果

## 三、执行分支
变量：`SYS` = 系统分区（如 `D:\Windows`），`ESP` = ESP 盘符（如 `Z:`）

**UEFI**
1. 搜 ESP：0 个 → 报错终止；1 个 → 自动用；**≥2 个 → 弹列表让用户选，绝不自动猜**
2. 无盘符则 `diskpart /s tmp.txt` 分配（内容 `select disk N` / `select partition M` / `assign letter=Z` / `exit`，用完删临时文件）
3. `bcdboot SYS\Windows /s ESP /f UEFI`
4. 兜底：`bootrec /scanos` + `bootrec /rebuildbcd`

**Legacy**（不需要 ESP）
```
bootrec /fixmbr
bootrec /fixboot
bootrec /rebuildbcd
```

**附加按钮**（同样调系统命令）
- 备份 BCD：`copy` → `BCD.bak`
- 清除旧 BCD：`ren ...\BCD BCD.old`
- 清除 EFI 启动项：`bcdedit`
- 添加 Windows Boot Manager 到固件启动项（`bcdboot` 成功 ≠ NVRAM 一定有条目）

## 四、UI 控件（极简）
Label 固件模式（只读）· ComboBox 选系统分区 · Label 分区表 GPT/MBR（选完自动刷新）· 日志 TextBox（只读）· 警告区（不匹配标红）· 按钮【备份 BCD】【一键修复】

## 五、必须守的规矩
1. 破坏性操作前一律确认框
2. 多 ESP 必须用户选
3. 全程捕获输出回显，便于定位失败在哪一步
4. 进程输出编码设 `Encoding.GetEncoding(936)`（PE 中文乱码）
5. 执行顺序：UEFI 优先 `bcdboot`，`bootrec` 只兜底

## 六、选型
**C# WinForms / WPF**。原生 Win32+WMI，PE 下零依赖免运行库。
Python+PyQt 开发快但要带运行库，PE 下体积大 → 不建议。

## 七、工具来源与加载策略（PE 里找不到 exe 怎么办）

**结论：把 exe 放进项目目录直接调用即可，不需要在 System32 里。**

实测本机（x64 Win10）两个目录：

| exe | x64 版（System32） | x86 版 | 大小 x64 / x86 | 除系统基础 DLL 外的依赖 |
|---|---|---|---|---|
| bcdboot.exe | ✅ | ❌ 本机无 | 253 KB / — | WINTRUST / CRYPT32 / imagehlp / RPCRT4 / bcrypt |
| bcdedit.exe | ✅ | ❌ 本机无 | 482 KB / — | CRYPTSP.dll |
| diskpart.exe | ✅ | ✅ 在 SysWOW64 | 155 KB / 147 KB | USER32 / VERSION / RPCRT4 |
| bootsect.exe | ✅ | ❌ 本机无 | 107 KB / — | 无 |
| bootrec.exe | ❌ | ❌ | 只在 WinRE / WinPE 里 | — |

依赖的全是任何 PE 必带的系统 DLL，没有任何"必须在 System32 才有权限"的东西。每套约 1 MB，**两套都带**也就 2 MB，随项目走无压力。

**x86 版从哪来**：x64 Windows 的 `SysWOW64` 只给 `diskpart` 提供 32 位副本，`bcdboot` / `bcdedit` / `bootsect` 在 x64 系统上**没有 32 位版**。要凑齐 x86 那套，只能整体从**32 位 Windows / 32 位 PE / 32 位安装镜像的 `sources\boot.wim`** 里抠 —— 而且必须同源同版本，别东拼西凑（混版本会出怪问题）。

**目录结构**
```
tools\
  x64\  bcdboot.exe  bcdedit.exe  diskpart.exe  bootsect.exe  bootrec.exe
  x86\  同上（bootrec 从 32 位 PE 抠）
  SOURCE.txt
```

**四条硬约束**
1. 架构必须匹配 —— 32 位 PE 跑不了 x64 exe，x64 PE 跑 x86 exe 还要看它带没带 WoW64（很多精简 PE 不带），所以**程序按目标 PE 架构选目录，不能写死一套**。用 `RuntimeInformation.OSArchitecture` 或 `Environment.Is64BitOperatingSystem` 判断，选中哪套在日志里打出来。
2. 版本别超车 —— 不要拿 Win11 的塞进 Win10 老 PE（新二进制可能导入老 ntdll 没有的符号）。取与 PE 同版本或更老的一档，Win10 21H2 最稳。
3. `bootrec.exe` 普通 Windows 不装，只能从 PE 自身的 `\Windows\System32\`，或安装 ISO 的 `sources\boot.wim` 里抠。
4. **每个 exe 都在 `tools\SOURCE.txt` 里登记：文件名、架构、文件版本号、来源镜像、md5**。这几条命令的行为跨版本有差异，出问题要能回溯到具体是哪一份。

**调用姿势**
- 用绝对路径调 `tools\x64\xxx.exe` 或 `tools\x86\xxx.exe`，不要指望 PATH。
- 不要往 PE 的 System32 里塞 —— `X:` 是 ramdisk，重启即失，被裁过的 PE 塞进去也未必生效。
- `bootrec` 必须和 `bootsect` 放同一目录（或临时把该目录加进子进程 PATH），它内部会去找 bootsect。
- 输出照旧按 936 编码捕获。

**加载策略**：先探系统自带（`%SystemRoot%\System32\x.exe` 在不在），在就用系统的（版本最配当前 PE），不在才 fallback 到项目内置；日志明确打一行"使用：系统自带 / 项目内置 xxx"。

**许可**：微软的 exe 不可再分发。自用或内部做 PE 盘无所谓；若要公开到 GitHub，把 exe 排除出仓库（`.gitignore`），另配"首次运行从本机或 PE 拷贝"的小脚本。

**终极兜底（连 bcdboot 都没有时）**：引导文件本来就躺在系统盘自己的 Windows 目录里 —— UEFI 抄 `SYS:\Windows\Boot\EFI\` 到 ESP 的 `EFI\Microsoft\Boot\`；Legacy 抄 `SYS:\Windows\Boot\PCAT\bootmgr` 到系统分区根；再用 `bcdedit /store` 建 BCD。不依赖任何外部 exe 也能修好。

## 八、补充坑（原对话记录里没有）

- `bootrec /rebuildbcd` 是**交互式**的（会问 y/n），直接 `ReadToEnd()` 会挂死 → 必须先 `/scanos` 或喂 stdin。
- 部分 PE 下 `bootrec /fixboot` 报"拒绝访问"，改用 `bootsect /nt60 SYS /mbr` 更稳。
- diskpart `assign letter` 若该分区已有盘符会失败，执行前先 `list volume` 查。
